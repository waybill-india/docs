waybill-arc search runs after intake resolves a query. It picks internal suppliers from the supplier network, hands them off to the [supervisor](/concepts/supervisor) (which sends RFQs), and runs up to three open-web discovery legs in parallel. The open-web legs run only when `SUPPLIER_SIMULATOR=false`, and each leg is enabled by its own key.

## What happens during search

When you call `POST /search/:requestID`, the search agent:

1. Reads the resolved query and selects the most relevant internal suppliers.
2. Hands the selected suppliers to the supervisor, which immediately sends RFQs.
3. If `EXA_API_KEY` is set, starts an Exa web search for marketplace listings and quotation-based suppliers on the open web. Poll [`GET /search/:requestID/web`](/api-reference/search/web) for results.
4. If `PARSEBOT_API_KEY` is set, scrapes Amazon, Flipkart, IndiaMART, and Alibaba for product listings. This completes before the response is sent; fetch [`GET /search/:requestID/marketplaces`](/api-reference/search/marketplaces) once.
5. If DigiKey (`DIGIKEY_CLIENT_ID` + `DIGIKEY_CLIENT_SECRET`) or Mouser (`MOUSER_API_KEY`) keys are set, queries their catalog APIs for live stock and pricing. This also completes before the response is sent; fetch [`GET /search/:requestID/distributors`](/api-reference/search/distributors) once.

## Search response

A successful search returns:

```json
{
  "requestID": "299cb5b9-4b9d-4c1a-9d51-3f2f0a4f0e21",
  "selections": [
    {
      "supplierID": "SUP-00142",
      "description": "Franchised distributor for STMicroelectronics",
      "reasoning": "Explicitly handles STM32 and has stock in region"
    }
  ],
  "supervisor": {
    "status": "awaiting_supplier_responses",
    "waitingFor": ["SUP-00142", "SUP-00187"]
  },
  "webSearchStarted": true,
  "marketplaceSearched": true,
  "distributorsSearched": true
}
```

- **`selections`** — why each internal supplier was chosen.
- **`supervisor`** — the initial supervisor state after RFQs are sent. If no internal suppliers matched, this is `null`.
- **`webSearchStarted`** — `true` when the Exa run was created. Poll [`GET /search/:requestID/web`](/api-reference/search/web) for results.
- **`marketplaceSearched`** — `true` when marketplace listings were stored. Fetch [`GET /search/:requestID/marketplaces`](/api-reference/search/marketplaces) once.
- **`distributorsSearched`** — `true` when distributor offers were stored. Fetch [`GET /search/:requestID/distributors`](/api-reference/search/distributors) once.

Each flag is `false` when that leg is disabled, unconfigured, or failed outright.

## Retry and idempotency

After a successful handoff to the supervisor, a second call to `POST /search/:requestID` returns `409`. If the first call returned `200` with `supervisor: null` (no internal suppliers), you may retry the call and it will reuse the same web search run.

## Web candidate kinds

When the Exa search completes, candidates have one of two `kind` values:

| Kind | Meaning | Fields to show |
| --- | --- | --- |
| `marketplace_listing` | Buy directly from a marketplace. | `productUrl`, `price` |
| `quotation_supplier` | Reach out for a quote. | `contactEmail`, `contactPhone`, `website` |

Any unverified field may be `null`. Web candidates, marketplace listings, and distributor offers are **not** part of the supervisor or RFQ flow. They are independent outreach lists you can present to the user alongside the internal supplier results.
