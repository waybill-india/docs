waybill-arc search runs after intake resolves a query. It picks internal suppliers from the supplier network, hands them off to the [supervisor](/concepts/supervisor) (which sends RFQs), and optionally starts a parallel Exa web search for open-web suppliers when `EXA_API_KEY` is configured. When `PARSEBOT_API_KEY` is configured, it also searches 11 online marketplaces for buy-now product listings.

## What happens during search

When you call `POST /search/:requestID`, the search agent:

1. Reads the resolved query and selects the most relevant internal suppliers.
2. Hands the selected suppliers to the supervisor, which immediately sends RFQs.
3. If `EXA_API_KEY` is set, starts an Exa web search for marketplace listings and quotation-based suppliers on the open web.
4. If `PARSEBOT_API_KEY` is set, searches 11 online marketplaces for matching products. See [Marketplace product search](#marketplace-product-search).

## Search response

A successful search returns:

```json
{
  "requestID": "299cb5b9-4b9d-4c1a-9d51-3f2f0a4f0e21",
  "selections": [
    {
      "supplierID": "SUP-00142",
      "description": "Franchised distributor for STMicroelectronics",
      "reasoning": "Explicitly handles STM32 and has stock in region"
    }
  ],
  "supervisor": {
    "status": "awaiting_supplier_responses",
    "waitingFor": ["SUP-00142", "SUP-00187"]
  },
  "webSearch": { "runId": "agent_run_01jabc123", "status": "running" }
}
```

- **`selections`** — why each internal supplier was chosen.
- **`supervisor`** — the initial supervisor state after RFQs are sent. If no internal suppliers matched, this is `null`.
- **`webSearch`** — present only when the Exa leg is enabled. Poll [`GET /search/:requestID/web`](/api-reference/search/web) for results.

## Retry and idempotency

After a successful handoff to the supervisor, a second call to `POST /search/:requestID` returns `409`. If the first call returned `200` with `supervisor: null` (no internal suppliers), you may retry the call and it will reuse the same web search run.

## Web candidate kinds

When the Exa search completes, candidates have one of two `kind` values:

| Kind | Meaning | Fields to show |
| --- | --- | --- |
| `marketplace_listing` | Buy directly from a marketplace. | `productUrl`, `price` |
| `quotation_supplier` | Reach out for a quote. | `contactEmail`, `contactPhone`, `website` |

Any unverified field may be `null`. Web candidates are **not** part of the supervisor or RFQ flow. They are an independent outreach list you can present to the user alongside the internal supplier results.

## Example web candidate

```json
{
  "kind": "quotation_supplier",
  "productUrl": null,
  "price": null,
  "supplierName": "Shenzhen Botai Automation Co.",
  "location": "Shenzhen, China",
  "contactEmail": "sales@botai.example.cn",
  "contactPhone": "+86 755 …",
  "website": "https://botai.example.cn",
  "sources": [
    { "url": "https://botai.example.cn/contact", "title": "Contact Us" }
  ]
}
```

## Marketplace product search

Marketplace product search looks up buy-now product listings on online marketplaces. Use it when the part can be bought directly instead of quoted. It runs in parallel with internal supplier selection and the Exa web search.

### Supported marketplaces

Every search queries all 11 marketplaces at once:

| Marketplace | `marketplace` value |
| --- | --- |
| Flipkart | `flipkart` |
| Amazon | `amazon` |
| eBay | `ebay` |
| IndiaMART | `indiamart` |
| Alibaba | `alibaba` |
| Micro Center | `microcenter` |
| Misumi | `misumi` |
| Bolt Depot | `boltdepot` |
| McMaster-Carr | `mcmaster` |
| Zoro | `zoro` |
| RobotShop | `robotshop` |

waybill-arc keeps the top 5 relevant products per marketplace. Alibaba listings whose minimum order quantity exceeds the requested quantity are dropped.

### Configuration

Marketplace search uses [parse.bot](https://parse.bot) scrapers and requires `PARSEBOT_API_KEY`:

```sh
PARSEBOT_API_KEY=your-parsebot-key
```

When `PARSEBOT_API_KEY` is unset, waybill-arc skips marketplace search. `POST /search/:requestID` then returns `marketplaceSearched: false`.

### Timing

Each marketplace call times out after 60 seconds. Calls can approach that limit, especially cold calls to scrapers that haven't run recently. `POST /search/:requestID` waits for the marketplace leg to finish, so allow up to about 60 seconds for the response.

### Partial failures

Each marketplace is queried independently. If one marketplace fails or times out, waybill-arc records an error for that marketplace only, and the other marketplaces still return products. The run's `status` is `failed` only when every marketplace fails.

```json
{
  "status": "completed",
  "products": [ { "marketplace": "amazon", "title": "STM32F103C8T6 Blue Pill Board", "price": "₹389" } ],
  "errors": [
    { "marketplace": "mcmaster", "error": "parse.bot mcmaster search_products failed with status 504: Gateway Timeout" }
  ]
}
```

Fetch results with [`GET /search/:requestID/marketplaces`](/api-reference/search/marketplaces).
