Poll the supervisor run to track RFQ progress, view incoming quotes, and read the final award recommendation. Call this endpoint after [`POST /search/:requestID/handoff`](/api-reference/search/handoff) (or [`POST /search/:requestID`](/api-reference/search/start)) returns a non-null `supervisor` object, then poll every 5–10 seconds until `status` is `completed`.

Each supplier runs in its own child thread under a coordinator. This endpoint returns the merged coordinator view. To read one supplier's thread in isolation, use [`GET /supervisor/:requestID/:supplierID`](#read-a-single-supplier-thread) below.

## Endpoint

```http
GET /supervisor/:requestID
```

## Request

<CodeGroup>

```bash cURL
curl http://localhost:3001/supervisor/299cb5b9-4b9d-4c1a-9d51-3f2f0a4f0e21
```

</CodeGroup>

## Response

### 200 — Run state

```json
{
  "requestID": "299cb5b9-4b9d-4c1a-9d51-3f2f0a4f0e21",
  "status": "awaiting_supplier_responses | in_progress | completed",
  "request": {
    "requestID": "…",
    "selectedSupplierIDs": ["SUP-00142", "SUP-00187"],
    "supplierChannels": {
      "SUP-00142": "email",
      "SUP-00187": "whatsapp"
    },
    "workflowPolicy": {
      "sendRfqs": true,
      "runQualification": true,
      "normalizeQuotes": true,
      "negotiate": true,
      "recommendAward": true
    },
    "selections": [
      {
        "supplierID": "SUP-00142",
        "description": "…the supplier's own profile from the supplier network…",
        "reasoning": "Franchised distributor explicitly handles STM32…"
      }
    ],
    "resolvedQuery": { }
  },
  "next": "…internal routing hint, ignore…",
  "interrupts": [ { "waitingFor": ["SUP-00142"] } ],
  "errors": [
    {
      "supplierID": "SUP-00187",
      "message": "Supplier workflow failed. Check the Arc server logs and retry the workflow."
    }
  ],
  "messages": [
    { "type": "human | ai | tool", "name": "rfq | supplier_responses | quotes | qualification | qualification_verdicts | counter_responses | negotiation | supplier_declined | supplier_withdrawn | supplier_failed | supplier_no_reply | award_recommendation", "content": "…" }
  ]
}
```

<ResponseField name="request.selections" type="array">
  Carries why each supplier was picked so the shortlist survives a page reload. It is `[]` for runs started before selections were persisted; fall back to `selectedSupplierIDs`.
</ResponseField>

<ResponseField name="request.supplierChannels" type="object">
  Map of `supplierID` to the channel used for that supplier (`email`, `whatsapp`, `simulator`, `voice`, or `sms`). Populated from the handoff payload and may differ per supplier for mixed-channel runs. Missing keys fall back to `request.channel`.
</ResponseField>

<ResponseField name="request.workflowPolicy" type="object">
  Which stages the coordinator will run. All flags default to `true`. See [`POST /search/:requestID/handoff`](/api-reference/search/handoff) for the meaning of each flag.
</ResponseField>

<ResponseField name="interrupts" type="array">
  Lists suppliers the coordinator is currently waiting for. Use this to show "waiting for reply" badges.
</ResponseField>

<ResponseField name="errors" type="array">
  Per-supplier failures recorded when a child workflow crashed. Each entry has `supplierID` and a human-readable `message`. The coordinator still awards over the remaining suppliers, so treat this as an in-band failure list, not a top-level run error.
</ResponseField>

<ResponseField name="messages" type="array">
  A timeline of the run. Includes stage messages from every child thread merged in supplier order, followed by the coordinator's `award_recommendation` when the run completes.
</ResponseField>

## Message names

The `messages` timeline includes per-stage entries (`rfq`, `supplier_responses`, `quotes`, `qualification`, `qualification_verdicts`, `counter_responses`, `negotiation`) plus four **terminal supplier markers** and the coordinator's final `award_recommendation`.

| Name | Meaning |
| --- | --- |
| `supplier_declined` | Supplier explicitly refused the RFQ. Nothing further is sent to them. |
| `supplier_withdrawn` | Supplier pulled out mid-negotiation after initially engaging. |
| `supplier_failed` | The supplier's child workflow crashed. The coordinator recorded a synthetic terminal state so it could still award over the remaining suppliers. The `content` is a JSON blob with `supplierIDs` and `error`. See also the top-level `errors[]` array. |
| `supplier_no_reply` | Supplier did not respond within the waiting window. |
| `award_recommendation` | The coordinator's single markdown award recommendation, appended once every child thread finishes. Render as markdown. |

Render every terminal marker in the timeline. Dropping them hides supplier outcomes users need to see (for example, why a supplier is not in the award).

## Reading structured payloads

Two `messages` entries carry JSON rather than prose. In both, the JSON array starts at the first `[` in `content`.

### `name: "quotes"`

One entry per selected supplier. Read the **last** `quotes` message, because it is refreshed after counter-offer rounds.

```json
[
  {
    "supplierID": "SUP-00142",
    "quoted": true,
    "unitPrice": 1.87,
    "currency": "USD",
    "moq": "1,000 pcs",
    "leadTime": "6 weeks",
    "packaging": "Tape and reel",
    "dateCode": "2023+",
    "stockQuantity": 1200,
    "balanceLeadTime": "800 pcs in 10 weeks",
    "notes": "Authorized distributor, full traceability",
    "raw": "…the supplier's reply verbatim…"
  }
]
```

Every field except `supplierID`, `quoted`, and `raw` may be `null` when the supplier did not state it. `quoted: false` means no commercial terms were given; render the supplier as awaiting a quote rather than dropping it, and fall back to `raw`.

### `name: "qualification_verdicts"`

One verdict per selected supplier.

```json
[
  {
    "supplierID": "SUP-00142",
    "disposition": "approved | excluded | review",
    "reasons": [
      "Authorized distributor for STMicroelectronics",
      "RoHS documentation provided"
    ]
  }
]
```

`review` means the assessment was inconclusive or silent about that supplier. Only `approved` suppliers proceed to negotiation and are eligible for award; `review` and `excluded` suppliers stop at qualification and are reported at award. The `qualification` message holds the full narrative for a details view.

## Read a single supplier thread

```http
GET /supervisor/:requestID/:supplierID
```

Returns the same shape as `GET /supervisor/:requestID` but scoped to one supplier's child thread (`<requestID>:supplier:<supplierID>`). Use it to render per-supplier detail views without reasoning about the merged coordinator timeline.

<CodeGroup>

```bash cURL
curl http://localhost:3001/supervisor/299cb5b9-4b9d-4c1a-9d51-3f2f0a4f0e21/SUP-00142
```

</CodeGroup>

The response includes the `supplierID` on the envelope:

```json
{
  "requestID": "299cb5b9-4b9d-4c1a-9d51-3f2f0a4f0e21",
  "supplierID": "SUP-00142",
  "status": "in_progress",
  "request": { },
  "messages": [ ],
  "interrupts": [ ],
  "errors": [ ]
}
```

## Errors

| Status | Body | Meaning |
| --- | --- | --- |
| 404 | `{ "error": "Request not found" }` | The `requestID` has no supervisor run. |
| 404 | `{ "error": "Supplier workflow not found" }` | `GET /supervisor/:requestID/:supplierID` was called with a `supplierID` that has no child thread. |
