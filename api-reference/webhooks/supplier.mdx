---

The supplier gateway calls `POST /webhook` when a supplier replies to an RFQ. The endpoint saves the reply and responds immediately. It then resumes the supervisor run in the background so it can qualify quotes, negotiate counter-offers, and progress toward the award recommendation. A UI does not need to call this endpoint.

## Endpoint

```http
POST /webhook
```

## Request body

<ParamField body="requestID" type="string" required>
  The UUID of the procurement request.
</ParamField>

<ParamField body="supplierID" type="string">
  Optional supplier identifier.
</ParamField>

## Example

<CodeGroup>

```bash cURL
curl -X POST http://localhost:3001/webhook \
  -H "Content-Type: application/json" \
  -d '{
    "requestID": "299cb5b9-4b9d-4c1a-9d51-3f2f0a4f0e21",
    "supplierID": "SUP-00142"
  }'
```

</CodeGroup>

## Response

### 200: Reply accepted

A `200` means the reply was accepted and saved. It does not mean the supervisor has resumed. Supervisor progress shows up shortly afterwards, so poll the request state rather than expecting it to change by the time this endpoint returns.

```json
{
  "received": true
}
```

## Errors

| Status | Body | Meaning |
| --- | --- | --- |
| 404 | `{ "error": "Request not found" }` | The `requestID` does not exist. |

## Background processing

If the background resume fails or is cut off, the reply stays unprocessed. waybill-arc retries unprocessed replies at startup and every 10 minutes, once any existing 15-minute claim on the reply expires. See [Acknowledgement and background processing](/guides/webhooks#acknowledgement-and-background-processing).
