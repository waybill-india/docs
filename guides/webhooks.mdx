waybill-arc pauses the supervisor while it waits for supplier replies. Three inbound webhook endpoints resume the run when replies arrive: one for the supplier gateway, one for Vapi voice and SMS events, and one for Meta WhatsApp Cloud API events. This guide covers how each webhook works, what payloads to expect, and how to configure them.

## Supplier gateway

`POST /webhook` is called by the supplier gateway when a supplier replies.

**Request body**

```json
{
  "requestID": "299cb5b9-4b9d-4c1a-9d51-3f2f0a4f0e21",
  "supplierID": "SUP-00142"
}
```

`supplierID` is optional. The endpoint returns:

```json
{
  "received": true
}
```

This resumes the supervisor run automatically. A UI does not need to call this endpoint directly.

## AgentMail email

Inbound email replies are dispatched to the handler registered in `src/webhook.ts`, which resumes the supervisor.

To register the webhook, run:

```bash
npm run channels:register-webhook -- https://your-host/webhook/email
```

Store the printed secret as `AGENTMAIL_WEBHOOK_SECRET`. AgentMail will sign inbound requests with this secret so the handler can verify them.

## Vapi voice and SMS

`POST /webhook/vapi` receives events from Vapi when a voice call ends or an SMS session is updated.

### Authentication

Vapi echoes back the `x-waybill-signature` header from the `server.headers` set on each transient assistant. The endpoint validates this header against `VAPI_WEBHOOK_SECRET`.

### Request matching

Requests are matched to a `(request_id, supplier_id)` pair through `channel_threads`:

- For `voice`, the match uses the Vapi call ID.
- For `sms`, the match uses the Vapi session ID.

### Event handling

Only two event types are acted on:

- `end-of-call-report` — voice call ended, resume the supervisor
- `session.updated` — SMS session updated, resume the supervisor

### Response codes

| Status | Meaning |
| --- | --- |
| `200 {}` | Event handled and the supervisor was resumed |
| `204` | Event ignored (unhandled type, unmapped call or session, or nothing new from the supplier) |
| `401` | Invalid webhook signature |
| `503` | Vapi webhook is not configured (`VAPI_WEBHOOK_SECRET` is unset) |

### Failure modes

Failures that happen after a call is dispatched do not arrive as HTTP errors. Instead, they appear as `endedReason` on the `end-of-call-report`:

- unanswered
- voicemail
- insufficient credits
- international dialing blocked (on free Vapi numbers)

Vapi exposes no SMS delivery status. Inbound SMS is US↔US only, so a non-US supplier can receive an SMS but cannot reply through Vapi.

## WhatsApp (Meta Cloud API)

`GET` and `POST /webhook/whatsapp` form the Meta WhatsApp Cloud API webhook. Meta calls this endpoint, not you. Point your Meta app's webhook URL here.

### Verification handshake

Meta sends a `GET` request when you register the webhook URL. The endpoint echoes `hub.challenge` when `hub.verify_token` matches `WHATSAPP_WEBHOOK_VERIFY_TOKEN`, and returns `403` otherwise.

### Authentication

Meta signs every `POST` with the `x-hub-signature-256` header, an HMAC-SHA256 hex digest of the raw request body keyed by `WHATSAPP_APP_SECRET`. The endpoint rejects requests whose signature does not match.

### Event handling

Every event is persisted to the WhatsApp message store. Inbound text messages are then matched to a request/supplier pair through `channel_threads` on the sender's `waId` and resume the supervisor. When several requests share the same `waId`, the most recently created request wins. Delivery statuses, unmapped senders, redeliveries of an already-recorded message, and non-text messages are recorded but deliberately ignored.

### Response codes

| Status | Meaning |
| --- | --- |
| `200 OK` | Event processed, including deliberately ignored events |
| `400` | Malformed JSON |
| `401` | Invalid signature |
| `500` | Persistence or agent dispatch failed; Meta redelivers with backoff, and the last-message-ID dedupe keeps redeliveries from double-resuming the run |
| `503` | WhatsApp channel is not configured (`WHATSAPP_*` variables unset) |

### Failure modes

Outbound send failures that happen after Meta accepts a message do not arrive as HTTP errors. Most notably, a free-form text sent outside the 24-hour service window fails with Meta error `131047`. These failures arrive as status events and are recorded on the message, so they never surface to the agent.

For endpoint reference, see [POST /webhook](/api-reference/webhooks/supplier), [POST /webhook/vapi](/api-reference/webhooks/vapi), and [GET + POST /webhook/whatsapp](/api-reference/webhooks/whatsapp). For channel setup and environment variables, see [Channels](/guides/channels).
