waybill-arc reads its configuration from a `.env` file in the repo root, validated by `src/config.ts`. Set the required keys for LLM calls and database connectivity, then add optional variables to tune agent behavior, enable channels, or wire observability.

## Required

| Variable | Description |
| --- | --- |
| `OPENAI_API_KEY` | OpenAI key for LLM calls |
| `DATABASE_URL` | Postgres connection string for LangGraph checkpoints and channel tables |

## Sourcing mode

| Variable | Default | Description |
| --- | --- | --- |
| `SUPPLIER_SIMULATOR` | `true` | `true` sources from the supplier simulator (RFQs, negotiation). `false` sources from the open web only, enabling the parallel Exa, marketplace, and distributor legs of `POST /search`. |
| `SUPPLIER_API_URL` | `http://localhost:3002` | Base URL for the supplier simulator exposing `GET /api/getAllSuppliers`. Unused when `SUPPLIER_SIMULATOR=false`. |

## Agent tuning

| Variable | Default | Description |
| --- | --- | --- |
| `CONFIDENCE_THRESHOLD` | `0.9` | Minimum confidence before intake resolves a query |
| `MAX_TOOL_ITERATIONS` | `15` | Cap on agent tool-call loops |

## Tracing (Langfuse)

| Variable | Description |
| --- | --- |
| `LANGFUSE_PUBLIC_KEY` | Langfuse public key; tracing disabled when unset |
| `LANGFUSE_SECRET_KEY` | Langfuse secret key; tracing disabled when unset |
| `LANGFUSE_BASE_URL` | Langfuse host, e.g. `https://us.cloud.langfuse.com` |

## Open-web discovery

Each key enables one open-web leg of `POST /search`. All legs require `SUPPLIER_SIMULATOR=false`.

| Variable | Description |
| --- | --- |
| `EXA_API_KEY` | Enables the parallel Exa web-search leg of `POST /search` |
| `PARSEBOT_API_KEY` | Enables the parallel marketplace-search leg (Amazon, Flipkart, IndiaMART, Alibaba listings via parse.bot; a `pmx_…` key from the parse.bot dashboard) |
| `DIGIKEY_CLIENT_ID` | DigiKey OAuth client ID; enables the DigiKey distributor-search leg (set with the secret) |
| `DIGIKEY_CLIENT_SECRET` | DigiKey OAuth client secret; both DigiKey keys must be set together |
| `MOUSER_API_KEY` | Mouser Search API key; enables the Mouser distributor-search leg (shared quota of about 30 calls/min and 1,000/day) |

## Email channel (AgentMail)

| Variable | Default | Description |
| --- | --- | --- |
| `AGENTMAIL_API_KEY` | — | Required to use the email channel |
| `AGENTMAIL_WEBHOOK_SECRET` | — | Svix signing secret for `POST /webhook/email` |
| `AGENTMAIL_INBOX_ID` | — | Use an existing inbox instead of creating one. Set this to a fixed address; without it a new inbox is created on each cold boot and supplier replies land somewhere nobody is watching |
| `AGENTMAIL_INBOX_USERNAME` | `procurement` | Username for the shared inbox created on first use |
| `EMAIL_LIVE_DELIVERY` | `false` | `false` routes every RFQ to `EMAIL_TEST_ADDRESS` instead of the supplier, so a run can be exercised end to end without contacting anyone real. Flip to `true` only when you mean to email actual suppliers |
| `EMAIL_TEST_ADDRESS` | — | Address that receives all RFQs while `EMAIL_LIVE_DELIVERY` is `false`. Required in that mode when `AGENTMAIL_API_KEY` is set |

## WhatsApp channel

The WhatsApp channel activates when the `WHATSAPP_*` Cloud API variables are set. Two variables guard live delivery:

| Variable | Default | Description |
| --- | --- | --- |
| `WHATSAPP_LIVE_DELIVERY` | `false` | `false` routes every RFQ to `WHATSAPP_TEST_NUMBER` instead of the supplier. Flip to `true` only when you mean to message actual suppliers |
| `WHATSAPP_TEST_NUMBER` | — | Number that receives all RFQs while `WHATSAPP_LIVE_DELIVERY` is `false`. Required in that mode when the WhatsApp channel is configured |

## Voice/SMS channel (Vapi)

| Variable | Default | Description |
| --- | --- | --- |
| `VAPI_API_KEY` | — | Required to use the `voice` or `sms` channel |
| `VAPI_PHONE_NUMBER_ID` | — | Vapi phone number placing outbound calls |
| `VAPI_WEBHOOK_URL` | — | Public URL of `POST /webhook/vapi`; inbound disabled if unset |
| `VAPI_WEBHOOK_SECRET` | — | Shared secret sent back as `x-waybill-signature` |
| `VAPI_SMS_PHONE_NUMBER_ID` | — | SMS-enabled US Twilio number imported into Vapi |

## Example `.env`

```sh
# Required
OPENAI_API_KEY=sk-...
DATABASE_URL=postgres://user:pass@host:5432/dbname

# Sourcing mode
# true: source from the supplier simulator (RFQs, negotiation).
# false: source from the open web only; SUPPLIER_API_URL is unused.
SUPPLIER_SIMULATOR=true
SUPPLIER_API_URL=http://localhost:3002

# Agent tuning
CONFIDENCE_THRESHOLD=0.9
MAX_TOOL_ITERATIONS=15

# Tracing (optional)
LANGFUSE_PUBLIC_KEY=pk-...
LANGFUSE_SECRET_KEY=sk-...
LANGFUSE_BASE_URL=https://us.cloud.langfuse.com

# Open-web discovery (optional; requires SUPPLIER_SIMULATOR=false)
EXA_API_KEY=exa-...
PARSEBOT_API_KEY=pmx_...
DIGIKEY_CLIENT_ID=...
DIGIKEY_CLIENT_SECRET=...
MOUSER_API_KEY=...

# Email channel (optional)
AGENTMAIL_API_KEY=am-...
AGENTMAIL_WEBHOOK_SECRET=whsec_...
AGENTMAIL_INBOX_ID=procurement@agentmail.to
AGENTMAIL_INBOX_USERNAME=procurement
EMAIL_LIVE_DELIVERY=false
EMAIL_TEST_ADDRESS=you@example.com

# WhatsApp channel delivery guard (optional)
WHATSAPP_LIVE_DELIVERY=false
WHATSAPP_TEST_NUMBER=+919999999999

# Voice/SMS channel (optional)
VAPI_API_KEY=vapi-...
VAPI_PHONE_NUMBER_ID=phone_...
VAPI_WEBHOOK_URL=https://your-host/webhook/vapi
VAPI_WEBHOOK_SECRET=shared-secret
VAPI_SMS_PHONE_NUMBER_ID=phone_sms_...
```
