waybill-arc uses Postgres for LangGraph checkpoints (agent memory), the channel tables (`supplier_contacts`, `channel_threads`), the `web_search_runs` table, and the browser login-capture tables (`browser_profiles`, `browser_login_sessions`). This page covers installing Postgres, creating a database, and running the migration script.

<Steps>
  <Step title="Install Postgres and create a database">
    Install Postgres 14 or later locally, or provision a managed instance such as Vercel Postgres. Create a database for waybill-arc.
  </Step>
  <Step title="Set DATABASE_URL">
    Add the connection string to your `.env` file:

    ```sh
    DATABASE_URL=postgres://user:pass@host:5432/dbname
    ```
  </Step>
  <Step title="Run migrations">
    Execute the migration script to create all tables:

    ```sh
    npm run migrate
    ```
  </Step>
</Steps>

## Tables created

The migration script sets up the following tables:

- **LangGraph checkpoint tables** — managed by LangGraph for agent state persistence across stages
- **`supplier_contacts`** — stores supplier addresses per channel (`supplier_id`, `channel`, `address`)
- **`channel_threads`** — maps `(request_id, supplier_id, channel)` to the provider thread ID so replies stay in-thread and inbound webhooks can recover request context
- **`web_search_runs`** — persists Exa web search run state and results
- **`browser_profiles`** — connector registry mapping `(user_id, site)` to a Browser Use `profile_id` with a `status` of `pending` or `connected`; stores only profile IDs, never cookies or credentials
- **`browser_login_sessions`** — active browser login-capture sessions (`session_id`, browser URLs, profile ID and name, optional `user_id` and `site`); rows expire 30 minutes after `created_at`

<Note>
  Vercel Postgres or any Postgres 14\+ instance works. The migration script is idempotent and safe to re-run.
</Note>
